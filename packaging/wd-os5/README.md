# HSYNC — WD My Cloud OS5 Package

This directory holds everything needed to build a `.bin` installer for the
**Western Digital My Cloud EX2 Ultra** (and other OS5-based My Cloud devices)
that can be installed through the stock admin Dashboard
(`Apps → Install an App manually`).

The package wraps the standalone `hsync` PyInstaller binary together with a
small web UI for configuring the service, controlling it (start/stop/restart)
and viewing its runtime log — all without SSH access.

## Target

| Item              | Value                                              |
| ----------------- | -------------------------------------------------- |
| Device            | WD My Cloud EX2 Ultra                              |
| SoC               | Marvell Armada 385 (Cortex-A9, dual-core 1.3 GHz)  |
| Architecture      | ARMv7 32-bit hard-float (`armv7l` / `armhf`)       |
| Firmware          | Stock My Cloud OS 5                                |
| glibc on device   | up to `GLIBC_2.30` (verified on firmware 5.x)      |
| Build base image  | `debian:buster` (`arm32v7`) — `glibc_2.28`         |
| Python on device  | not required (PyInstaller `--onedir`, standalone)  |

The build base is **Debian 10 (buster)** so the produced binary depends only
on `GLIBC ≤ 2.28`, which is comfortably below the `2.30` ceiling exposed by
the stock OS5 firmware.

## Build flow

The builder image bakes the third-party dependencies **and** the application
sources as cached layers, so the slow ARMv7 native compilation (a static
OpenSSL 3, cryptography, zstandard, the PyInstaller bootloader) happens once at
`docker build` time instead of on every run. Editing application code rebuilds
only the cheap source layers and reuses the cached dependency install; the
per-run container does nothing but produce the frozen binary.

```
host (x86_64)                    qemu-user-static (armv7)
─────────────                    ────────────────────────
compile.sh --target wd-ex2-ultra-os5
    │
    ├── stage build context ───────────────► build/wdos5/ctx/
    │       (hsync-client + hsync-common manifests & sources)
    │
    ├── docker build -f Dockerfile.builder ──► hsync-wdos5-builder:armv7
    │       debian:buster + Python 3.12 + Rust + static OpenSSL 3 + Poetry
    │       + poetry install (deps, cached layer) + baked sources
    │
    ├── docker run … pyinstaller --onedir ──► build/wdos5/bin/hsync/
    │       (deps already installed; only the binary is produced)
    │
    ├── generate icon  ─────────────────────► Apkg/hsync.png
    │
    ├── stage Apkg/ + binary + apkg.rc ────► build/wdos5/hsync/
    │       (apkg.rc has __HSYNC_VERSION__ replaced by pyproject version)
    │
    ├── docker build -f Dockerfile.mksapkg ──► hsync-wdos5-mksapkg:bullseye
    │       debian:bullseye + libxml2.so.2 + OpenSSL 1.1.1 (bf-cbc)
    │
    └── docker run … mksapkg-OS5 -E -s -m MyCloudEX2Ultra
            │       (staging parent mounted at /work; cached tool bind-mounted)
            └─► dist/wd-ex2-ultra-os5/MyCloudEX2Ultra_hsync_<ver>.bin
```

The source `Apkg/` tree is **never mutated** by the build: the binary and
the rendered `apkg.rc` are written to a disposable staging copy under
`build/wdos5/hsync/`, and `mksapkg-OS5` packs that copy.

`mksapkg-OS5` itself runs inside a small `debian:bullseye` container rather
than on the host: the prebuilt tool is linked against `libxml2.so.2` and shells
out to `openssl bf-cbc` to sign `apkg.sign`, neither of which modern hosts
provide (e.g. Ubuntu 26.04 ships libxml2 `.so.16` and OpenSSL 3 hides bf-cbc
behind the legacy provider). The container carries both, so packaging is
reproducible regardless of the host distribution.

## Runtime layout on the NAS

| Path                                            | Purpose                                       |
| ----------------------------------------------- | --------------------------------------------- |
| `/shares/Volume_1/Nas_Prog/hsync/`              | Installed package (binary, scripts, web)      |
| `/mnt/HD/HD_a2/hsync/data/`                     | Default synced directory (user-configurable)  |
| `/mnt/HD/HD_a2/hsync/config/hsync.env`          | Persistent configuration written by the UI    |
| `/mnt/HD/HD_a2/hsync/log/hsync.log`             | Runtime log (rotated by the OS)               |
| `/var/www/hsync/`                               | Symlinks to `Apkg/web/*` for the admin UI     |

The config path lives on the data volume so it survives package re-installs
and firmware upgrades.

## Configuration

The web UI exposes the following options (all map 1:1 to `hsync` CLI flags).
The shipped defaults are tuned for using the NAS as a **backup target**: it is
the authoritative LAN **master** and **ignores client-side deletions**, so the
backup never loses files because a source host removed them. Adjust from the UI
for other use cases.

The LAN transport is **HTTPS/WSS-only** (protocol `lan/1`): the master serves
over TLS with a persistent self-signed identity and advertises its certificate
fingerprint, which slaves pin (Trust-On-First-Use). There is no plain-HTTP
option to configure.

| UI field            | CLI flag                                       | Default                          |
| ------------------- | ---------------------------------------------- | -------------------------------- |
| Sync path           | `-p / --path`                                  | `/mnt/HD/HD_a2/hsync/data`       |
| Mode                | `--lan-mode` vs `-s / --server`                | LAN                              |
| Role                | `--force-master` + `--sync-direction`          | Master (NAS authoritative)       |
| Bucket              | `-b / --bucket`                                | `hsync`                          |
| LAN shared key      | `HSYNC_LAN_KEY` env var                        | _empty_                          |
| Strict pairing      | `--require-pairing`                            | off                              |
| Group               | `--lan-group`                                  | _empty_                          |
| Discovery timeout   | `--discovery-timeout`                          | `10` (`0` = wait indefinitely)   |
| Persistent LAN      | `--no-lan-persistent/`                         | enabled                          |
| Server URL          | `-s / --server`                                | _empty_                          |
| API key             | `HSYNC_API_KEY` env var                        | _empty_                          |
| Watch mode          | `-w / --watch`                                 | on (service mode)                |
| Resync interval     | `-i / --interval`                              | `0` (off)                        |
| Ignore deletions    | `--ignore-delete`                              | on (backup-friendly)             |
| Bandwidth limits    | `--max-bandwidth-upload/--download`            | unlimited                        |
| Compression         | `--no-compression`                             | enabled                          |
| Delta transfer      | `HSYNC_DELTA_ENABLED`                          | enabled                          |
| Delta min size      | `HSYNC_DELTA_MIN_FILE_SIZE`                    | `262144` (256 KB)                |
| Delta min size LAN  | `HSYNC_DELTA_MIN_FILE_SIZE_LAN`                | `1048576` (1 MB)                 |
| Min free disk space | `--min-free-disk-space`                        | service default                  |
| Max inbound size    | `--max-download-size`                          | service default                  |
| Max concurrent      | `--max-concurrent-transfers`                   | `5`                              |
| Mass-delete guard   | `--mass-delete-guard/--no-mass-delete-guard`   | on                               |
| Mass-delete thresh  | `--mass-delete-threshold`                      | `50` (0 = disabled)              |
| Mass-delete percent | `--mass-delete-percent`                        | `50` (0 = disabled)              |
| Verbose log         | `-v / --verbose`                               | off                              |

The role selector maps to the existing CLI primitives:

| Role        | Flags                                           | Meaning                              |
| ----------- | ----------------------------------------------- | ------------------------------------ |
| Auto        | _(none)_                                        | Bidirectional, automatic election    |
| Master      | `--force-master`                                | NAS holds the authoritative copy     |
| Slave       | `--sync-direction download-only`                | NAS is a read-only replica           |
| Never master| `--never-master`                                | Syncs both ways but never becomes master |

## Locales

The web UI ships with the same five locales as the desktop / Android clients:
**EN, IT, DE, ES, FR**. Language is auto-detected from
`navigator.language` and can be overridden from the UI header.

## Log viewer

The **View log** button opens an overlay that tails the runtime log at
`/mnt/HD/HD_a2/hsync/log/hsync.log` in near real time. The browser polls
`log_get.php`, which returns only the bytes appended since the last byte offset
it received, so updates feel live without re-transferring the whole file; the
first load shows the tail window (last 64 KiB) and each poll is capped (256 KiB)
so a write burst cannot return an unbounded payload. The endpoint is read-only
with a fixed path (no user input selects the file). The overlay offers
**Auto-scroll**, **Clear** and **Close**; polling stops when the overlay is
closed.

## Notes for maintainers

* The package **version** is taken from `pyproject.toml` at build time and
  injected into `Apkg/apkg.rc`. There is no separate version to bump here.
* The `mksapkg-OS5` tool is fetched from the upstream
  [WDCommunity/wdpksrc](https://github.com/WDCommunity/wdpksrc) repository
  the first time `compile.sh --target wd-ex2-ultra-os5` runs and cached
  under `packaging/wd-os5/.cache/`.
* **Containerized mksapkg.** The cached tool is executed inside the
  `hsync-wdos5-mksapkg:bullseye` image (built locally from
  `Dockerfile.mksapkg`, not published to any registry) rather than on the host.
  The prebuilt x86-64 binary links against `libxml2.so.2` and signs `apkg.sign`
  by shelling out to `openssl bf-cbc`; Debian Bullseye still provides both,
  whereas modern hosts ship libxml2 `.so.16` and gate bf-cbc behind the OpenSSL
  3 legacy provider. The staging dir's parent is bind-mounted at `/work` (since
  `mksapkg-OS5` drops the `.bin` in the parent of its CWD) and the container
  runs as the host uid so artifacts stay caller-owned.
* The builder image is built locally and is **not** published to any
  registry. Re-run `compile.sh --target wd-ex2-ultra-os5 --clean` to force a
  rebuild.
* **Host-uid PyInstaller.** The `docker run … pyinstaller` step runs as the
  host uid (`-u "$(id -u):$(id -g)"`, with `HOME`/`XDG_CACHE_HOME` pointed at
  `/tmp` so the cache is writable) so the bundle it writes to `build/wdos5/`
  stays caller-owned. Otherwise PyInstaller would run as root and the later
  `build/` cleanup of a plain `./compile.sh` (native) build would fail with
  *Permission denied*.
* The **dependency install** is a cached Docker layer keyed on
  `pyproject.toml` + `poetry.lock` (for both `hsync-client` and the
  `hsync-common` path-dependency). It is recompiled only when those manifests
  change; editing application code reuses the cached layer and rebuilds only
  the cheap source layers. The slow ARMv7 native build (cryptography,
  zstandard, the PyInstaller bootloader) therefore happens once and is
  persisted by BuildKit, surviving interrupted runs.
* **OpenSSL 3 (ARMv7).** `cryptography` (pinned `>=48,<50`, resolving to
  49.0.0) refuses to compile against OpenSSL < 3.0.0, but Debian Buster ships
  only 1.1.1. The builder therefore compiles a **static** OpenSSL 3
  (`OPENSSL_VERSION` in `Dockerfile.builder`, SHA256-pinned) into
  `/opt/openssl3` and points the Rust `openssl-sys` build at it via
  `OPENSSL_DIR` + `OPENSSL_STATIC=1`, so the `cryptography` extension embeds
  OpenSSL 3 statically and the bundle stays self-contained on the NAS. The
  CPython `ssl` module keeps using the system libssl 1.1.1. Bumping
  `OPENSSL_VERSION` requires updating `OPENSSL_SHA256` in lock-step. On amd64
  this layer is unused (prebuilt manylinux `cryptography` wheels apply).
